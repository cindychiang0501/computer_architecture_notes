NOTE 03 · DYNAMIC SCHEDULING

記分板排程
Scoreboarding

記分板把指令、功能單元與暫存器的狀態集中記錄，讓處理器可以動態判斷哪一條指令現在能安全地發射、執行與寫回。

核心觀念

記分板排程（Scoreboarding）是一種動態排程（dynamic scheduling）方法。處理器使用記分板記錄三類資訊：指令目前位於哪個階段、每個功能單元（Functional Unit, FU）是否忙碌，以及每個暫存器的最新結果由哪個功能單元產生。指令只有在不會造成結構危障（Structural Hazard）或資料危障時，才會進入下一個階段。

Issue：發射

找到空閒且類型符合的功能單元後配置指令；若沒有空間，指令必須等待。

Read Operands：讀運算元

等來源暫存器沒有尚未完成的生產者，再讀取運算元。

Execute：執行

運算元就緒後啟動功能單元，完成時間依加法器、乘法器等單元而不同。

Write Result：寫回

確認不會讓較早指令讀到錯誤值後，才把結果寫回暫存器。

指令範例

本例假設：使用簡化的 RISC-V 風格指令與暫存器命名；有一個加法單元與一個乘法單元；記分板可追蹤每個功能單元的 Busy、Op、Fi、Fj、Fk、Qj、Qk 與運算元就緒狀態；忽略實際 cycle 數與同週期衝突的仲裁細節。
# I1 先產生 t0；I2 讀取 t0，因此有 RAW 相依
I1: add  t0, t1, t2       # 發射到 Add FU，產生 t0
I2: mul  t3, t0, t4       # 等 I1 寫回 t0 後才能讀取
I3: add  t5, t6, t7       # 若 Add FU 忙碌，可能等待 Issue

# 記分板的簡化追蹤
# I1: Issue → Read Operands → Execute → Write Result
# I2: Issue → 等待 t0 就緒 → Read Operands → Execute → Write Result

I1 發射後，記分板會在暫存器結果狀態中標記 t0 的生產者是加法單元。I2 可以先被發射到乘法單元，但在 Read Operands 階段必須等 I1 完成並寫回 t0，這是 RAW（Read After Write）真實資料相依。I3 則可能因為唯一的加法單元正在處理 I1 而暫時無法發射，形成結構危障。

常見混淆

  • 記分板不是單純的指令佇列。它同時追蹤功能單元使用情形、暫存器結果來源與指令階段，目的是判斷何時可以安全前進。
  • RAW 不能被消除。I2 真的需要 I1 產生的 t0，所以仍要等待資料；記分板只能安排等待時機。
  • WAR 與 WAW 需要特別防止。記分板會延後讀取或寫回，避免較晚指令的動作破壞較早指令仍需要的資料；這和使用暫存器重新命名的 Tomasulo 方法不同。
  • 發射成功不代表指令已經執行完。指令可能已配置功能單元，卻仍在等運算元或等待寫回條件。

自我檢查題

若 I1: add t0, t1, t2 正在加法單元執行，而 I2: mul t3, t0, t4 已經發射到乘法單元，I2 為什麼不能立刻讀取 t0 並執行？這是哪一種危障？

展開查看答案

I2 不能立刻使用 t0，因為目前的 t0 是由 I1 產生，而 I1 尚未完成寫回；I2 必須等待正確值產生後才能讀取並執行。這是 RAW（Read After Write）危障，也就是實際存在的資料相依。
