NOTE 04 · DYNAMIC SCHEDULING

Tomasulo 演算法
Tomasulo Algorithm

Tomasulo 演算法讓處理器可以動態排程指令：指令先進入保留站等待需要的運算元，資料準備好後再執行，結果則透過共同資料匯流排廣播給等待者。

核心觀念

Tomasulo 演算法（Tomasulo Algorithm）是一種動態排程（dynamic scheduling）方法。保留站（Reservation Station, RS）會記錄指令、已取得的運算元，以及尚未產生資料的來源標籤；暫存器別名表（Register Alias Table, RAT）則指出某個暫存器目前正等待哪個標籤產生結果。

發射（Issue）

指令分配到可用的 RS，已知的運算元直接存入；未知的運算元記下生產者標籤。

等待（Wait）

RS 監看共同資料匯流排（Common Data Bus, CDB），等待自己的來源標籤廣播。

執行（Execute）

所有運算元就緒後，RS 將指令送到功能單元執行，不必讓整條 pipeline 停住。

寫回（Write Result）

結果帶著標籤廣播；等待相同標籤的 RS 取得資料並更新自己的等待欄位。

指令範例

本例假設：使用 RV32I RISC-V 暫存器命名；ADD_RS 可執行加法；MUL_RS 可執行乘法；每個保留站一次接收一條指令；以標籤 M1、A1 表示生產者；忽略實際週期數與 CDB 同時廣播的仲裁細節。
# I1 先產生 t0；I2 需要 t0，因此會在 MUL_RS 等待
I1: add  t0, t1, t2       # 發射至 ADD_RS，完成後廣播 M1
I2: mul  t3, t0, t4       # 發射至 MUL_RS；Vj = t0 尚未就緒，Qj = M1

# 結果廣播後，I2 取得 t0 並繼續
# CDB: M1, value = t1 + t2
# MUL_RS: Qj == M1 → Vj = value, Qj = ready
# 下一步：I2 的兩個運算元都就緒，MUL_RS 執行 mul

以簡化的狀態追蹤來看，I2 一開始不必阻塞整個處理器，只要在 MUL_RS 中保留。當 I1 的結果以 M1 標籤在 CDB 廣播時，I2 發現自己的 Qj = M1，便把廣播值填入 Vj；此時 I2 的運算元齊全，就能送進乘法單元執行。

連結 Data Hazards

這個例子是 Data Hazards 筆記中的 RAW（Read After Write）：I2 要讀取 I1 寫入的 t0，所以在 I1 廣播結果以前，I2 不能使用正確資料。Tomasulo 並沒有消除 RAW 的真實資料相依，而是讓 I2 在保留站等待，避免不必要地停住其他無關指令。

對 WAR（Write After Read）與 WAW（Write After Write）而言，Tomasulo 會以保留站標籤與暫存器重新命名（register renaming）區分不同生產者，讓不同指令不必爭用同一個暫存器名稱。這能消除名稱造成的假相依；但 RAW 的值相依仍然存在，仍須等資料廣播後才能執行。

RAW：不能消除

I2 真正需要 I1 的結果，必須等 CDB 廣播完成。

WAR：重新命名可避免

後面的寫入使用新的標籤，不會覆蓋前面指令要讀的舊值。

WAW：重新命名可避免

不同寫入各自對應不同標籤，再依架構規則更新可見的暫存器狀態。

重點

保留站處理等待時機；標籤與重新命名處理名稱衝突。

常見混淆

  • 保留站不是暫存器本身。它是保存等待中指令與運算元狀態的硬體項目；暫存器別名表則追蹤暫存器目前對應的結果來源。
  • 廣播不是代表所有指令立刻完成。只有等待該標籤且其他運算元也已準備好的指令，才能開始自己的執行。
  • 重新命名不會消除 RAW。它主要消除 WAR 與 WAW 這類名稱相依；真正的資料相依仍必須等待生產者結果。

自我檢查題

若 I1: add t0, t1, t2 的結果標籤是 A1，而 I2: sub t3, t0, t4 已進入保留站並記錄 Qj = A1，I2 何時可以開始執行？這和 RAW、WAR、WAW 哪一種危障有關？

展開查看答案

I2 要等到 CDB 廣播 A1 的結果，將資料填入保留站的 Vj，且另一個運算元 t4 也已就緒後，才能開始執行。這是 RAW：I2 讀取 I1 尚未產生的結果。重新命名可以處理 WAR、WAW，但不能讓 I2 在資料尚未產生時提前使用它。
