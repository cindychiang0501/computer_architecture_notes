NOTE 05 · CONTROL FLOW

推測執行
Speculation

分支的結果要到後面的 pipeline 階段才知道，處理器可以先猜一條路並提前工作；猜對就省下等待，猜錯就丟掉錯誤路徑的結果。

核心觀念

推測執行（Speculative Execution）是處理器在尚未確定控制流程結果前，先取出並執行預測路徑上的指令。分支預測（Branch Prediction）提供「下一條可能走哪裡」的判斷；推測執行則是處理器根據這個判斷，先把指令送入 pipeline 工作。

預測正確

預測路徑就是實際路徑，已完成的工作可以繼續，結果依序提交（commit）。

預測錯誤

清除錯誤路徑上的年輕指令（flush），恢復正確 PC，再從正確目標重新取指。

指令範例

本例假設：使用 RV32I RISC-V 架構；每條基本指令為 4 bytes；採用經典五階段 pipeline（IF、ID、EX、MEM、WB）；beq 在 EX 階段判定結果；處理器使用分支預測先決定要取順序路徑或目標路徑，並忽略 delay slot。
# t0 = 目前計數器，t1 = 結束值
loop:
0x3000:  beq  t0, t1, done   # 預測：不成立（not taken）
0x3004:  addi t0, t0, 1      # 先推測執行
0x3008:  jal  zero, loop     # 先推測執行
done:
0x3010:  addi a0, t0, 0

當處理器在 0x3000 讀到 beq 時，若預測器預測「不成立」，PC 會先走向 0x3004，於是 addi 和後面的指令可以提前進入 pipeline。此時它們仍是推測中的工作，尚未能在分支結果確認前對架構狀態做不可逆的提交。

如果 t0 ≠ t1，預測正確：分支確實不成立，推測執行的指令成為正確路徑，pipeline 可以繼續前進。若 t0 = t1，預測錯誤：處理器在 EX 階段發現分支應該跳到 done，就會 flush 0x3004 之後、尚未提交的錯誤路徑指令，將 PC 重新導向 0x3010，再從正確路徑取指。這會造成幾個 pipeline cycle 的分支錯誤代價。

常見混淆

  • Branch Prediction 是「猜哪一條路」。它是對條件分支結果或目標位址的預測，例如猜 branch taken 或 not taken。
  • Speculative Execution 是「先照猜的路做」。它是利用預測結果提前取指、解碼與執行；因此兩者相關，但不是同義詞。
  • 預測錯誤不等於程式邏輯錯誤。處理器會丟棄尚未提交的錯誤路徑工作，恢復正確 PC；代價主要是浪費的 cycle 與重新填滿 pipeline 的時間。
  • 推測結果不應直接破壞架構狀態。實作通常透過 reorder buffer 等機制保留暫存結果，等指令確定位於正確路徑且可依序提交後，才更新可見狀態。

自我檢查題

處理器預測 beq 不成立，因此先執行順序路徑上的兩條指令。稍後在 EX 階段發現分支其實成立。這兩條指令應該保留還是丟棄？PC 接下來要指向哪裡？

展開查看答案

應該丟棄這兩條尚未提交的推測指令，因為它們位於錯誤的順序路徑。處理器會 flush 錯誤路徑上的年輕指令，並將 PC 重新導向分支的目標位址，再從正確路徑取指與執行。這就是一次 branch misprediction penalty。
